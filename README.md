# RuStoreDL — исходный код Android-приложения

Неофициальное Android-приложение для поиска приложений в каталоге RuStore и скачивания установочных файлов с серверов RuStore. Проект использует собственный скрипт сборки — Gradle и Android Studio не требуются.

| Параметр | Значение |
|---|---|
| Версия приложения | `2.4` (`versionCode` `56`) |
| Application ID | `ru.rustoredl` |
| Минимальная версия Android | Android 8.0 (API 26) |
| Целевая версия | API 37 (`targetSdkVersion`) |
| Автор, указанный в EULA приложения | Trykath |
| Исходный комплект | `RuStoreDL-src-public-v2.4-vc56.zip.txt` |
| SHA-256 исходного комплекта | `c178111107223c842452d566112060a3f057a9a3dd5b63f96f1597e1a5c10960` |

Исходный комплект проверен и распакован в корень репозитория; внешний ZIP не добавлен. Версию и параметры приложения можно сверить с `AndroidManifest.xml`. Описание ниже относится к этому снимку исходников и не гарантирует, что сторонние API или ссылки обновлений останутся неизменными.

> **Публичный репозиторий:** релизные ключи подписи, пароли (`keystore.info`) и собранные APK намеренно не включаются. Для публикации релиза используйте собственный ключ, храните его вне репозитория и настройте защищённые секреты CI. APK, `.idsig`, локальные ключи и build-артефакты исключены через `.gitignore`.

## Как это работает

Приложение использует внутренний API клиента RuStore:

1. `GET https://backapi.rustore.ru/applicationData/overallInfo/{пакет}` —
   карточка приложения. Нужен заголовок `ruStoreVerCode` (код версии клиента
   RuStore); исходное значение — `110802`, а при ответах `400/417/419`
   приложение пытается автоматически подобрать допустимое значение (см. ниже).
2. `POST https://backapi.rustore.ru/applicationData/download-link`
   с телом `{"appId": N, "firstInstall": true}` — временная ссылка на CDN.
3. Скачивается ZIP, внутри — APK (или несколько APK, если приложение split).
4. Установка через системный `PackageInstaller` (умеет split-APK).
   Нужно разрешить этому приложению устанавливать неизвестные приложения;
   подтверждение установки выполняет Android.

## Сетевые обращения и разрешения

- Для каталога и ссылок загрузки используется внутренний API RuStore
  (`backapi.rustore.ru`); файл скачивается с CDN по временной ссылке, которую
  возвращает API. Это не публичный стабильный API, и RuStore может изменить его.
- Проверка обновления самого RuStoreDL обращается к
  `https://rslmod.ru/rustoredl/update.json`.
- В `AndroidManifest.xml` заявлены интернет и состояние сети; `QUERY_ALL_PACKAGES`
  нужен экрану проверки установленных приложений; `REQUEST_INSTALL_PACKAGES`
  запускает системный сценарий установки. Также заявлены разрешения для
  фоновых загрузок/заданий, перезапуска заданий после перезагрузки и уведомлений.
  Запись в общую папку «Загрузки» через `WRITE_EXTERNAL_STORAGE` нужна только
  на Android 8–9 (API 28 и ниже); на Android 10+ используется MediaStore.
- Согласно EULA из исходного комплекта, история хранится на устройстве в
  зашифрованном виде; сетевое поведение следует сверять с кодом перед сборкой
  и распространением.

## Android 17 и подпись v4 (v1.9)

- `targetSdkVersion=37`; минимальная поддерживаемая версия — Android 8.0 (API 26).
  `build.sh` выбирает самую свежую установленную платформу из `$SDK`, поэтому
  для сборки нужен Android SDK с платформой API 37 или новее.
- Подпись **v1+v2+v3+v4**: v4 — это файл-компаньон `RuStoreDL.apk.idsig`
  (создаётся автоматически рядом с APK). Он нужен только для ускоренной
  `adb install --incremental` на Android 11+; обычная установка использует
  v2/v3 из самого APK, `.idsig` при ручной установке не требуется.

## Подпись своим ключом

**Вариант А (рекомендуется) — собирать сразу своим ключом.** Передайте путь к
своему keystore и пароль через переменные окружения (`KS`, `KS_PASS`, при
необходимости `KS_ALIAS`); подробная команда приведена в разделе «Сборка».
Если алиас не указан, скрипт выберет первый `PrivateKeyEntry`. Ожидаемый
отпечаток сертификата синхронизируется с ключом автоматически.

**Вариант Б — переподписать готовый APK.** Тогда при сборке нужно ОТКЛЮЧИТЬ
встроенную проверку подписи (иначе приложение не запустится после переподписи):

```bash
NO_SIG_CHECK=1 bash build.sh          # собираем с отключённой проверкой
# затем переподписываешь RuStoreDL.apk своим ключом:
zipalign -f 4 RuStoreDL.apk aligned.apk
apksigner sign --ks my.keystore --out final.apk aligned.apk
```
Компромисс: слой «проверка подписи» отключён для всех, кто ставит этот APK.
Остальные слои (пиннинг, обфускация, анти-отладка, шифрование истории) работают.

**Правила одного ключа:** все обновления должны быть подписаны тем же ключом —
Android не даст обновить приложение другим ключом без удаления. Смена ключа
возможна только через ротацию v3 (`apksigner sign --next-signer ...`) заранее,
до публикации. Ключ и пароли хранить в тайне; потеря ключа = потеря апдейтов.

## Обновления по воздуху (2.2.6)

Приложение проверяет `https://rslmod.ru/rustoredl/update.json` при каждом запуске:
- диалог в стиле приложения «Обновление доступно» → «Обновить» (скачивание
  с прогрессом в диалоге, сверка SHA-256, установка поверх) или «Позже»;
- уведомления не используются — только диалог внутри приложения;
- Настройки → «Загрузки и обновления» → «Обновлять приложение» (вкл. по умолчанию).
TLS-пиннинг на собственный хост не распространяется — обычное системное доверие.

## Надёжные загрузки (2.2)

- **Фоновая служба загрузки**: свернул или смахнул приложение — скачивание продолжается,
  в шторке висит прогресс с кнопкой «Отменить»; по завершении — уведомление;
- **Докачка после обрыва**: пропала сеть — загрузка продолжается с места разрыва
  (по каждому из сегментов), а не начинается заново;
- **«Уже скачано»**: если эта версия уже лежит в истории с живыми файлами, приложение
  предложит установить сохранённое, а не качать повторно (на главном экране и в «Обновлениях»);
- **Автоочистка** (Настройки → «Загрузки», по умолчанию выключена): APK успешно
  установленной версии стирается — из кэша и из «Загрузок»; запись в истории остаётся.

## Прогрев при старте (2.1)

Класс `App` (Application) при старте процесса в фоне читает SharedPreferences
и прогревает PackageManager: главный поток на холодном старте не ждёт диска —
профилактика ANR, когда система перегружена (подкачка, VPN-демоны и пр.).

## Защита (v1.6)

| Слой | Что делает | Где |
|---|---|---|
| Release-ключ подписи | собственный ключ для публикации (не debug); хранить вне репозитория и не передавать публично | локальный файл, исключён `.gitignore` |
| Проверка подписи | при каждом запуске сверяет SHA-256 своего сертификата с эталоном; не совпало — APK пересобран чужим ключом, приложение не запускается | `SecurityUtil.signatureOk` |
| TLS-pinning | соединения доверяют серверу, только если leaf-сертификат имеет наш SPKI-пин; иначе — стандартная проверка цепочки. MITM-прокси (Charles и т.п.) не проходят | `SecurityUtil`, `res/xml/network_security_config.xml` |
| Запрет cleartext + только системные CA | пользовательские CA не принимаются, HTTP запрещён | network_security_config |
| R8-обфускация | внутренние классы/методы переименованы (карта — `mapping.txt`); в dex не осталось имён вроде `signatureOk`/`discoverVerCode` | `proguard-rules.pro` |
| Анти-отладка | watchdog каждые 3 сек: подключён отладчик → процесс убивается | `SecurityUtil.startWatchdog` |
| Анти-хуки | детект Xposed/Frida (файлы + классы) → запуск блокируется; root → предупреждение | `SecurityUtil.hookedEnvironment` |
| Шифрование истории | история скачиваний шифруется AES-256-GCM ключом из Android Keystore (ключ не покидает устройство) | `CryptoUtil` |
| Запрет backup | `allowBackup=false` — историю не вытащить через adb backup | манифест |

Эталонный хэш подписи хранится в `res/values/security.xml` и **автоматически**
обновляется `build.sh` из файла ключа при каждой сборке (не рассинхронизируется).

**Если RuStore сменит TLS-сертификат** (ротация пинов) — получить новые SPKI:
```bash
openssl s_client -connect backapi.rustore.ru:443 -servername backapi.rustore.ru -showcerts </dev/null
# для каждого сертификата цепочки:
openssl x509 -pubkey -noout | openssl pkey -pubin -outform DER | openssl dgst -sha256 -binary | base64
```
и обновить `TLS_PINS` в SecurityUtil.java + `<pin-set>` в network_security_config.xml.

**Честно о границах:** клиентская защита без собственного сервера не абсолютна —
root даёт атакующему доступ ко всему процессу. Этот набор делает автоматическую
модификацию/перехват дорогими и заметными (переподпись ловится, MITM не проходит,
отладка убивает процесс, реверс замедлен обфускацией), но не является «доказуемой»
защитой: якорь настоящей безопасности — серверная сторона.

## Параллельная загрузка (v1.12)

CDN RuStore поддерживает Range-запросы, поэтому файл качается **8 соединениями
параллельно** (константа `DL_SEGMENTS`): файл делится на равные части, каждый
поток докачивает свою через `Range: bytes=a-b`, пишет в общий файл через
`RandomAccessFile.seek()` (позиции не пересекаются).

Замер на живом CDN (21 МБ): 1 соединение — 1,6 МБ/с, 8 — 6,4 МБ/с,
12 — 7,2 МБ/с (далее насыщение). 8 — оптимум для мобильных сетей.

- Общий прогресс — `AtomicLong`; каждая часть продвигает свой `segPos[k]`.
- Ретраи: сетевой сбой сегмента → переподключение со своего места (до 6 раз).
- Пауза/продолжение/отмена работают как раньше, но теперь сразу для всех
  8 соединений (тот же `pauseLock`).
- Если сервер перестал отдавать 206 — `Fallback`: автоматический откат на
  одноканальное скачивание. Мелкие файлы (<1 МБ) и серверы без Range — сразу
  одноканально.
- Корректность проверена: собранный из 8 частей файл байт-в-байт совпал
  с оригиналом (SHA-256).

## Пауза и отмена скачивания (v1.4)

Во время скачивания кнопка «Скачать и установить» заменяется панелью:
тонкий прогресс-бар + «❚❚ Пауза» и «Отмена».

- **Пауза** — флаг `dlPaused`: цикл чтения замечает его, закрывает HTTP-соединение
  и поток блокируется на `pauseLock`. Недокачанный файл хранится как
  `cache/rustore_dl.zip.part`.
- **Продолжить** — соединение открывается заново с заголовком
  `Range: bytes=N-`; CDN RuStore отвечает `206` и отдаёт хвост, файл дописывается.
  Если сервер перестанет поддерживать Range (ответ не `206`) — скачивание
  автоматически начнётся с нуля.
- **Отмена** — флаг `dlCancelled` будит поток, выбрасывается `Cancelled`,
  недокачанный файл удаляется, UI возвращается в исходное состояние.
- Состояние загрузки (`dlActive`, `dlPaused`, `dlDone`, `dlTotal`) — `static volatile`:
  переживает поворот экрана и пересоздание Activity, панель управления
  восстанавливается в `onCreate()`.
- Обновление статуса троттлится до ~4 раз/сек, чтобы не грузить UI-поток.

## Проверка обновлений установленных приложений (v1.1)

Раздел «Обновления приложений» в шторке:

- берёт установленные пользовательские приложения (системные, Google/com.android
  и сама RuStoreDL исключаются); на Android 11+ нужен `QUERY_ALL_PACKAGES`;
- для каждого пакета запрашивает витрину: `GET overallInfo/{package}`;
- **сравнение**: `versionCode` витрины > установленного `versionCode`
  (`PackageInfo.getLongVersionCode()`); если кодов нет — сравнение `versionName`
  по числовым сегментам (`cmpVersion`);
- «Обновить» в один тап — тот же конвейер, что на главной
  (`performDownload` → download-link → ZIP → APK → PackageInstaller),
  прогресс и «Отмена» прямо в строке списка; одновременных скачиваний — по одному;
- галочка «Сохранять копию APK в „Загрузки“» с главной действует и здесь;
- защита от бесполезных обновлений:
  - подпись витрины (`signatures`, SHA-256) не совпадает с подписью установленного
    → предупреждение «⚠ другая подпись» (такое обновление не установится поверх);
  - витрина требует более новый Android (`minSdkVersion`) → пункт без кнопки
    с пояснением «Витрина требует Android X+»;
- иконки берутся с витрины (`iconUrl`), размер — `fileSize`; проверка идёт
  в 4 потока (бережно к лимитам сервера) с прогрессом «Проверяю N из M»;
- Настройки прокручиваются (2.1): все карточки доступны на экранах любой высоты,
  чипы интервала фона не перекрываются низом экрана;
- **Фоновая проверка обновлений (v1.4, выключена по умолчанию)**: системный
  JobScheduler (без сторонних библиотек). Интервал 1/3/6/12/24 ч, опция
  «только Wi-Fi» (по умолчанию вкл), не работает на низком заряде, переживает
  перезагрузку (persisted). Найдены обновления → уведомление (тап — в раздел
  «Обновления»); включено автообновление → установка той же подписи прямо в фоне.
  Для уведомлений на Android 13+ запрашивается POST_NOTIFICATIONS при включении.
- **Автообновление при запуске (v1.3, выключено по умолчанию)**: если включить,
  при каждом запуске RuStoreDL сам проверяет установленные приложения и
  последовательно скачивает и запускает установку обновлений — **только для
  приложений с той же подписью** (и подходящим minSdk): несовместимые пропускает,
  ошибки проверки не мешают остальным; если пользователь начал своё скачивание,
  автоцикл останавливается. Установка каждой обновы подтверждается системно.
- **Список исключений из автообновления (v2.1)**: Настройки → «Список
  исключений» → «Добавить приложение» — выбор из установленных (список
  с иконками и поиском); тап по записи — убрать; долгий тап
  на приложении в разделе «Обновления» — исключить/вернуть. Исключённые
  не проверяются и не устанавливаются автообновлением ни при запуске,
  ни в фоне; раздел «Обновления» их по-прежнему показывает.
- **Настройка «Показывать приложения с другой подписью»** (включена по умолчанию):
  если выключить — такие приложения исчезают из списка, в итоге появляется
  «· скрыто по подписи: N»;
- параллельные скачивания не конфликтуют: пока идёт загрузка (живой поток!),
  вторая вежливо отклоняется; «залипший» флаг от прерванной загрузки блокировать
  не может — защита ориентируется на живой поток, а пауза дольше 10 минут
  завершает загрузку сама;
- итог: «Найдены обновления: X из N · нет в RuStore: Y · скрыто по подписи: Z
  · не удалось проверить: W».
  «Нет в RuStore» — приложение просто отсутствует в каталоге (404/400 витрины),
  это не ошибка; прочие сбои (сеть, лимиты 429/503) повторяются до 3 раз
  с растущей выдержкой (0.9 → 1.8 с) и только потом попадают в счётчик ошибок. `RuStoreApi.NotFound` отделяет это от реальных сбоев.
  Тап по строке статуса открывает список непроверенных с причинами (таймаут,
  обрыв соединения, сбой сервера). Предупреждение о подписи показывается один
  раз — красной строкой в карточке, без дублей в строке версий.

 Поиск по ссылке / имени пакета, карточка приложения (иконка, версия, размер).
- **Встроенный браузер RuStore (v1.5)**: кнопка «Браузер RuStore» на главной
  разворачивает WebView с rustore.ru (каталог/поиск/страницы приложений —
  прямо в приложении). Открыл страницу приложения → пакет сам подставляется

  конфигурацией «не ночь» — тёмная тема сайта в WebView местами нечитаема);
  кнопка «Назад»: история браузера → сворачивание браузера → закрытие шторки →
  выход (на Android 13+ через OnBackInvokedCallback, predictive back);
  TLS-пины действуют и в WebView
  (сертификат сайта совпадает с запином); «Назад» — по истории WebView,
  ещё раз — свернуть браузер; свёрнутый браузер сохраняет страницу.

  есть в RuStore новее — список, предупреждения о подписи/совместимости,
  обновление в тап.
- Скачивание APK с CDN RuStore и установка через системный PackageInstaller
  (split-APK ставится целиком одной сессией).
- **Галочка «Сохранять копию APK в „Загрузки"»** (состояние запоминается):
  - Android 10+: через MediaStore, без разрешений;
  - Android 8–9: напрямую в `Download/` (по запросу выдаётся разрешение на запись);
  - один APK → файл `pkg_vВерсия.apk`, split → подпапка `Download/RuStoreDL/pkg_vВерсия/`.
- **Экран «История скачиваний»**:
  - список всего скачанного: аватар-буква, название, пакет, версия, размер, дата,

  - «Очистить» в шапке — кэш + копии + история целиком.
  История хранится в `files/history.json`, APK-кэш — в `cache/install/`.

## Сборка

Поддерживаемый сценарий в комплекте — Linux с Bash; скрипт использует GNU
`readlink`, `find` и `sort -V`. Нужны:

- JDK 11+ (`javac`, `keytool`, `jar`);
- Python 3;
- Android SDK: платформа API 37 или новее и Build Tools с `aapt2`, `d8`,
  `zipalign` и `apksigner` (можно установить через Android SDK Manager или
  `sdkmanager`; Android Studio не требуется);
- R8 JAR — опционально для минификации и обфускации. По умолчанию скрипт ищет
  его по адресу `/tmp/r8.jar`; задайте `R8JAR` для другого расположения.

Установите Android SDK Platform 37 и совместимые Build Tools, затем выполните:

```bash
SDK="$HOME/Android/Sdk" ./build.sh
```

Скрипт выбирает самую свежую платформу, найденную в `$SDK`. Если R8 не найден,
сборка переключается на `d8` без обфускации — для публикационного релиза
установите R8 и проверьте вывод скрипта.

По умолчанию при первой сборке создаётся локальный `debug.keystore` с тестовым
ключом. Такой APK предназначен только для разработки; им нельзя обновить
установку, подписанную другим ключом. Файл ключа игнорируется Git.

Для релизной сборки используйте свой защищённый ключ и передайте параметры
сборки через окружение или защищённые секреты CI (не добавляйте пароль в Git):

```bash
SDK="$HOME/Android/Sdk" \
R8JAR="/path/to/r8.jar" \
KS="/secure/path/release.keystore" \
KS_PASS="$RELEASE_KEY_PASSWORD" \
KS_ALIAS="$RELEASE_KEY_ALIAS" \
./build.sh
```

Скрипт обновляет `res/values/security.xml` ожидаемым SHA-256 сертификата,
собирает `RuStoreDL.apk` и `.idsig` в корне проекта. APK, `.idsig` и
`mapping.txt` не предназначены для коммита и исключены через `.gitignore`.
Подпись выполняется в режимах v1, v2, v3 и v4. Все последующие релизы должны
использовать совместимый ключ подписи.

Этапы сборки: `aapt2 compile/link` → `javac` → `R8` (или `d8`, если R8 не задан)
→ упаковка `classes.dex` → `zipalign` → `apksigner`.

## Публикация GitHub Release

Workflow `.github/workflows/publish-release.yml` собирает APK на GitHub Actions,
подписывает release-ключом и создаёт GitHub Release с `RuStoreDL.apk` как asset.
Workflow запускается вручную; тег должен совпадать с `versionName` в манифесте.
На `main` успешная сборка публикуется автоматически, а для публикации из другой
ветки нужно явно включить вход `publish_release`. Для запуска сначала добавьте в
`Settings → Secrets and variables → Actions` следующие repository secrets:

- `RUSTOREDL_KEYSTORE_BASE64` — keystore в Base64 (Linux: `base64 -w0 release.keystore`);
- `RUSTOREDL_KEYSTORE_PASSWORD` — пароль keystore и ключа (скрипт использует один пароль для обоих);
- `RUSTOREDL_KEY_ALIAS` — alias ключа подписи.

Добавляйте значение Base64 непосредственно в GitHub Secret и не вставляйте его в чат.
Используйте тот же release-ключ, которым должны подписываться обновления
установок приложения. Не передавайте keystore или пароль в чат и не коммитьте
их. Затем в GitHub откройте **Actions → Build and publish signed APK → Run
workflow**, укажите тег, совпадающий с `versionName` (текущий — `v2.5`), и при
запуске не из `main` включите `publish_release`. Собранный `.idsig` не публикуется:
для обычной установки достаточно подписи APK.

## Автоподбор кода версии клиента (ruStoreVerCode)

RuStore проверяет заголовок `ruStoreVerCode` на попадание в допустимое окно
и отвечает разными статусами:

| Статус | Значение |
|---|---|
| `200` | всё хорошо |
| `404` | код версии принят, но приложение не найдено |
| `400` | заголовка нет или это не число |
| `417` | версия клиента **слишком старая** |
| `419` | версия клиента **слишком новая** |

Приложение не хранит код жёстко: стартовое значение `110802` лежит в
SharedPreferences, и при ответе `400/417/419` автоматически запускается подбор:

1. Проба тем же запросом с текущим кодом.
2. Если `417` — удваиваем значение вверх; если `419` — делим пополам вниз,
   пока не упрёмся в окно (`200/404`).
3. Если ступень перепрыгнула узкое окно — бинарный поиск между границами.
4. Найденное значение сохраняется и используется во всех последующих запросах.

На живом API подбор сходится за 8–9 проб (первые 1–7 секунд), после чего
значение кэшируется и тратится ноль лишних запросов. Логика: `api()`,
`apiStatus()`, `discoverVerCode()` в MainActivity.java.

## Тонкости

- Требования к устройству: Android 8.0+ (minSdk 26).
- `FLAG_MUTABLE` у PendingIntent обязателен с Android 12 — иначе система
  не может дописать результат установки в callback-intent.
- Split-APK: части складываются в одну сессию PackageInstaller.
- Если RuStore поменяет не только окно версий, но и сами эндпоинты,
  поправить нужно константу `API` в MainActivity.java.
